# Publishing the action to GitHub's Marketplace

## In plain words

GitHub's **Marketplace** is the store where people find ready-made steps for their workflows. Being listed there is free, and it is the main way strangers discover an action. GitHub lists an action only if:

1. it is in a **public** repository;
2. its `action.yml` is at the **top** of that repository, and there is only one;
3. its name is **unique** ("Parinama Verify" was free on 11 November 2026);
4. the owner has accepted the **GitHub Marketplace Developer Agreement** and uses **two-factor sign-in**.

Ours lives in `product/verify/`, next to pkv's code, so it can't be listed from this repository. Instead, a small repository, [broly18814/parinama-verify-action](https://github.com/broly18814/parinama-verify-action), holds only the action. Decision D-045 records why this route was chosen over moving the file.

## In engineering terms

| File here | What it is |
|---|---|
| `build_action.py` | Makes `action.yml` from `product/verify/action.yml`. The only changes are one extra step that downloads the pkv wheel from PyPI, pinned by URL and SHA-256, and `PYTHONPATH` pointing at the unpacked wheel. |
| `action.yml` | Generated by `build_action.py`; never edit it by hand. A self-check (`product/verify/tests/test_marketplace_action.py`) fails if it is out of date or pins a version other than the package's. |
| `README.md` | The Marketplace page (the action repository's front page). |

The `marketplace-action` job in `.github/workflows/self-checks.yml` runs this exact action on every upload of this repository. That job downloads from PyPI, checks the fingerprint and runs pkv, so a broken copy is caught before it is published.

## Each release

1. Release pkv as usual: bump the version, tag `pkv-vX.Y.Z`, publish to PyPI.
2. Update `VERSION`, `WHEEL_URL` and `WHEEL_SHA256` in `build_action.py`. Take the URL and hash from PyPI's page for the release, and check that the hash equals the GitHub release's `SHA256SUMS`. Then run `python3 product/action/build_action.py`.
3. Run `scripts/check-all.sh`, then commit and push. Wait for the robot: the `marketplace-action` job must pass.
4. Run `scripts/publish-action.sh`. It copies the files into the action repository, commits them and tags `vX.Y.Z`. It refuses to change a tag that already exists.

## The founder's one-time step on GitHub's website (needs your sign-in)

1. Open **https://github.com/broly18814/parinama-verify-action/releases/new?tag=v0.2.1**.
2. Tick **"Publish this Action to the GitHub Marketplace"**. If GitHub asks, read and accept the **Marketplace Developer Agreement** and turn on two-factor sign-in. Only you can accept the agreement: it binds you, not the assistant.
3. Choose the categories **Testing** (primary) and **Continuous integration** (secondary).
4. Release title: `Parinama Verify 0.2.1`. Then click **Publish release**.

Later releases only need step 1 with the new tag, plus the tick in step 2.
